# Books web client — G2 selected Orval adapter

**Generator selected: Orval 8.41.0.** This directory is the single supported
TypeScript / TanStack Query client foundation. The **Kubb** comparison lives
separately in `experiments/g2-client-spike/`, not in the application's npm
dependencies. G3 adds the actual React list/details/forms.

`src/generated/orval` is disposable and built from **ProtocolIA v0.3**
`examples/books-paging-v03/contract.json` through the verified Java Basic
OpenAPI HTTP profile. The canonical contract is never edited here. Source
`src/api/http.ts` and `src/api/cache.ts` are handwritten and preserved on
regeneration.

From the repo root:

```sh
sh examples/books-web/prepare.sh
cd examples/books-web
npm ci
npm run generate
npm run typecheck
npm run verify:contract
npm run verify:regen
```

The API is **not deployed with credentials embedded in client sources**.
Call `configureTransport({baseUrl, getHeaders})` at runtime; client hooks
(`useListBooks`, `useGetBook`, `useCreateBook`, `useAdjustStock`) are
generated by Orval and can be used from G3 React components. Error responses
throw typed `ApiHttpError` containing status and payload. Undefined error
bodies remain `unknown` until G0 defines truthful response schemas.

`createBookAndRefresh` / `adjustStockAndRefresh` and their React hook
counterparts invalidate all cached page variants plus the matching book
detail on successful mutations only. `verify:contract` compares these
explicit rules to the ProtocolIA resource/capability manifests and rejects
semantic drift. Authorization always remains enforced by Spring backend.

The Docker G2 integration suite boots a **separate loopback Spring Boot
instance**, not a live production service, and uses real typed HTTP requests
to test paging, auth, 201, 400/401/403/404/409, atomic restock and cache
invalidation. See `docs/G2_TYPESCRIPT_CLIENT_EVIDENCE.md` for outcomes.

**Not included:** generated UI, RJSF, production OIDC, SQL/persistence, or a
claim of developer-time savings.
