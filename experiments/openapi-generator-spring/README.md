# G1 — OpenAPI Generator Spring Boot 4 parity experiment

**State:** FUNCTIONAL SPIKE VERIFIED on branch SHA `7c6111e138a6d4573b89ca497c1b977fa53bac26`. The additional error-dispatch regression test in this branch is pending exact-head validation until the next build. **Do not yet adopt OpenAPI Generator as the default Java compiler.**

This experiment consumes **exactly** the target-specific OpenAPI 3.1 generated by
`protocolia compile-bundle` from [Books v0.3](../../examples/books-paging-v03/contract.json).
Neither that source contract, the existing ProtocolIA Java backend, nor frozen
P4 experiments are modified.

## Architecture and toolchain

- OpenAPI Generator **7.26.0** (`spring`), `delegatePattern=true`, `useSpringBoot4=true`, `useJackson3=true`, `useResponseEntity=false`, `useSpringBuiltInValidation=true`, `useTags=true`.
- Generated/throwaway source: five DTOs, Books/Default API interfaces, generated MVC controllers, delegates and `ApiUtil.java`. `ApiUtil.java` is an essential generated supporting file, selected explicitly through `supportingFiles=ApiUtil.java`; **all other supporting files, including generated POM, are excluded**.
- **User-owned and never overwritten:** root `app/pom.xml` (Spring Boot 4.1.1, Java 21), `Application.java`, `DemoSecurity.java`, `BookInventory.java`, `BooksDelegate.java`, `HealthDelegate.java`, application config, test classes and script checking the capability manifest.
- Server-side demo security maps five declared ProtocolIA operations to trusted, reviewed HTTP matchers; fail-closed `anyRequest().denyAll()`, Basic auth for test accounts only. Allowing only internal `DispatcherType.ERROR` preserves real 400/409/404 without exposing an ordinary external `/error` request. OAuth2/OIDC is a separate G4 target.
- The real business store is in-memory. No generated SQL, no database migrations, no fake auto-implemented domain method.

## How to verify

From repo root with Docker:

```bash
docker build -f experiments/openapi-generator-spring/Dockerfile -t protocolia-g1 .
docker run --rm -p 10000:10000 \
  -e PORT=10000 \
  -e PROTOCOLIA_USER=local-owner \
  -e PROTOCOLIA_PASSWORD='choose-a-long-local-demo-password' \
  -e PROTOCOLIA_SCOPES=catalog.read,catalog.write \
  protocolia-g1
```

The Docker build compiles the actual v0.3 bundle, verifies manifest-to-policy
mapping, generates Java APIs/models **twice in independent trees** and compares
the results (zero Java diff), compiles the full Boot 4.1.1 app, and executes
existing **five real HTTP JUnit tests** plus the delegate completeness test
and the additional internal-error dispatch regression. In-memory stock
adjustments must remain atomic after eight parallel writes. The generated
default 501 handlers are **not** accepted as success; `DelegateCompletenessTest`
requires explicit override of all declared HTTP operations.

## G1 decision, evidence, and unresolved issues

See [G1 execution report](../../docs/G1_OPENAPI_GENERATOR_EVIDENCE.md) for exact tested SHAs, failures, release pins, observed HTTP results and rollout decision.

**Important tradeoff:** this external-generator pilot currently needs about
**174 nonblank lines** across five handwritten Java classes versus **78
nonblank lines** for the previous Books `CatalogHandlers.java`; generated
sources and tests are excluded in both counts. The pilot adds user-owned
security and wire adapters that were generated by ProtocolIA's previous
backend. These numbers **do not prove a productivity improvement**. Conversely,
an upstream Java generator lowers the maintenance burden of handwritten
controllers/DTO code in ProtocolIA itself. Accept or reject the default
replacement only with additional corpus/API security and regeneration evidence.
