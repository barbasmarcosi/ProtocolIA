# P3-B3 local privilege separation and P3-B4 cost reservations

## Isolated approval service (P3-B3)

The Linux approval daemon is started as `python -m protocolia.operator_service --config /ABSOLUTE/private-config.json`, under a dedicated, host-managed OS user (not the model process). It owns a 0700 ledger directory, private 0600 host policy/registry/HMAC files and a Unix domain socket with mode 0600. It accepts only preview, prepare, approve, execute and revoke requests with strict message shapes and a 64-KiB envelope limit. Linux SO_PEERCRED checks peer UID against an explicit host allowlist, or fails closed on platforms without kernel peer credentials. It reloads host configuration and resource grants for every operation.

Model-facing clients may prepare and inspect a proposed plan but must NEVER own the private Ed25519 operator key, the HMAC key, the Docker socket or a host account allowed to write the approval files. In production, the approved operator interface must live behind its own independently authenticated user account and make an offline signature, which this service verifies. A copied signature authorizes only the exact one read-only plan during its short lifetime; revocation invalidates replay. All lower-level approval functions are privileged Python APIs and should remain unreachable outside this service.

The CI spins up this server in a *separate Python process* and sends real Unix socket messages, generates an offline operator signature from a distinct subprocess and performs an actual isolated Docker read. It also tests a denied peer UID, malformed JSON, forged approval, privileged RPC-field injection, policy edits and permissions. For an actual deployment, operators must separately control OS user enrollment, socket directory ACLs, service restart, alerting and key rotation. There is no deployed SSO/MFA account service; verifying key ownership is not equivalent to verifying a physical human. Do not expose it on a TCP/HTTP listener.

## Budget reservation and verified usage (P3-B4)

CostLedger is a provider-neutral metering primitive in a host-owned private directory; it does not invoke any model or paid provider. All monetary amounts are integer micro-USD. A trusted metering authority signs a bounded price quote with an HMAC key in a private 0600 file. The executor can reserve at most the pre-established scope ceiling, atomically across concurrent callers, before the first paid call. A started reservation is durable and *cannot* be refunded or retried automatically after an ambiguous crash. A trusted usage adapter signs the actual usage receipt; the ledger rejects unknown, altered, duplicate, non-integer or above-reservation usage, and reconciles unused reservations only when signed settlement is verifiable. Ceilings cannot be silently increased mid-scope. This fail-closed behavior intentionally ties up budget after uncertain provider execution until a separate operator reconciliation workflow is built.

The signing methods sign_quote and sign_usage are host-only examples of trusted adapters: a model cannot be trusted to mint cost or usage evidence. This is not a complete pricing integration. A real provider connector must independently check its own price limits, generate an exact worst-case cost quote, reserve, persist the started marker before any network call, capture independently verified provider usage, settle or quarantine, and never release started reservations on a guessed timeout. This project has not executed any real paid provider or verified live billing. CostLedger must not be advertised as zero-risk online payment reconciliation.

## Remaining P3 requirements

An actual OIDC/WebAuthn-enrolled identity frontend and lifecycle, real provider or writable effect connectors with proven crash/compensation semantics, true multi-external-effect recovery, and hostile daemon/container escape testing are not yet verified. The single-Docker-read broker remains restricted; no new privileged execution capability is automatically enabled by the budget ledger. Keep P3 issue #4 open until these gates have independent evidence.
