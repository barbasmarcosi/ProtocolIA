## Scope

Versioned `resources.json` sidecar (schema `0.1`) binds **existing** v0.2 operations and models to explicit resource identity, roles, input/read views, action labels and cache-invalidation targets. The compiler validates one detail/create operation and bounded named actions. The sample deliberately contains **no list** operation, since the existing Java target cannot truthfully generate query-parameter pagination yet.

CLI: `PYTHONPATH=src python -m protocolia compile-bundle examples/stock-change/protocolia/contract.json --profile java-spring-basic-demo --resources examples/stock-change/protocolia/resources.json --domain-errors examples/stock-change/protocolia/http-errors.json --out /tmp/catalog-bundle`

The output consists of **nine** deterministic files: original `ir.json`, `openapi.json`, `payload.schema.json`, `types.ts`, new `resource-ir.json`, `ui-manifest.json`, `capability-manifest.json`, `generation-manifest.json`, plus ownership `manifest.json`. The generated API adds `x-protocolia-resource`, operation-role/action-ID and explicit tags for mapped endpoints. Historical v0.1/v0.2 default artifacts and the previous standalone `compile-http` profile remain unchanged.

Resource role checks reject unrecognized keys, missing/duplicate bindings, mismatched path identity and types, fake list/delete support, guessed authorizations, unknown UI fields, missing write invalidation and unsupported models. No autogenerated SQL, OAuth identity mapping, Java code substitution or React runtime claimed.

A separate `diff-bundle` CLI compares old/new contracts plus old/new resource sidecars; protocol capability/effect changes are conservative breaking changes even if an OpenAPI wire-only checker declares compatibility. It does not replace oasdiff.
