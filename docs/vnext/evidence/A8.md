# A8 — Compensating cancellation, exactly-once stock restitution

## Objective and contract boundary

A8 adds a bounded business primitive to ProtocolIA: from **one declarative TypeSpec contract**, generate atomic cancellation of an existing inventory reservation and refund its stock **exactly once**, on both modular Spring Boot/JDBC and NestJS/pg. The A7 debit and allocation insert remain atomic. This is not a general arbitrary compensating workflow engine.

Source: `examples/vnext/inventory-reservations/contracts/main.tsp` (two entities `Part` and `Allocation`). The `Allocation.status` required string property has `@initial("active")`; the existing `createAllocation` uses `@reserve("Part", "available", "partSku", "units")`.

The new TypeSpec operation is:

```typespec
@route("/api/allocations/{number}/cancel")
@post @behavior("transition", "Allocation", "status")
@transition("active", "cancelled")
@release("Part", "available", "partSku", "units")
@capability("allocations.write")
op cancelAllocation(@path number: string):
  Allocation | NotFound | Conflict | BadRequest | Unauthorized | Forbidden;
```

The compiler validates field types, positive allocation units, the required foreign key, its parent stock field with nonnegative minimum, mandatory matching `@reserve` create operation, correct state initial/source, and a **terminal destination state**. The supported action has no body and cannot be public. Invalid contracts or unknown reserve fields are rejected before generation. Both adapters also independently verify release metadata and require the inventory write capability alongside allocation write authority.

### Generated runtime semantics

1. Check authorization before writing (both allocation and inventory write capabilities).
2. Atomically change one allocation `active → cancelled` with `UPDATE allocation ... WHERE number=:key AND status='active' RETURNING part_sku,units`.
3. If no row was updated, distinguish unknown ID (HTTP 404) from already processed (HTTP 409).
4. Credit exactly the returned allocation units to the referenced parent stock **within the same PostgreSQL transaction**. Bound the sum with `available <= 2147483647 - units` so integer overflow fails safely (HTTP 409).
5. Commit both updates together; on any error **ROLLBACK** both. Spring uses existing `@Transactional`; Nest acquires one `pg` connection, `BEGIN/COMMIT/ROLLBACK` and releases it.
6. Keep the same UI manifest semantics: contract-derived actions are available only for applicable state and granted capability; no entity-specific cancellation JSX was introduced.

This prevents duplicate refunds when ten clients compete to cancel the same reservation. Cancellation is not implemented as DELETE, and status cannot be overwritten by a PATCH or chosen as `cancelled` on CREATE.

Restoring the precondition and retrying cancelled it once and brought stock to the integer maximum, with no double credit.

## Limits and invariants NOT proven

- This is **one allocation and one stock item per transaction**, not multi-line orders, arbitrary n-table workflows, partial releases, timed expiry, payment reversals, event/outbox publishing, or distributed exactly-once guarantees.
- Within this bounded API, exactly-once means a successful `active → cancelled` status transition credits stock only once, even under concurrent requests. A privileged DB operator can still change rows out-of-band.
- **A7 existing installations cannot yet safely be upgraded in place** to this A8 fixture: adding a new mandatory `status` state field is outside the supported additive A5 migration profile. The A8 sample is generated against fresh isolated DBs. No claim of a production upgrade path.
- Production IAM/OIDC, audit history, external backups, recovery from infrastructure failures and Docker Engine `compose up` still need independent work.
- Existing React/Vite UI and manifest compile, but **a targeted A8 Chromium click journey was NOT RUN**. The Render public URL only serves the build-success marker, not a publicly deployed generated inventory application.
