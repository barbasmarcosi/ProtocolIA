## A14.1 — Generic guarded reference reassignment

- Separate application contract: `examples/vnext/facility-maintenance-a14/contracts/main.tsp`. Do not modify or retrospectively rescore A13.
- Operation: `@behavior("reassignReference", entity, fkField, fkField)`, `@audit(fkField)`, distinct non-public `@capability`.
- Body: exactly `{ "expected": "old FK", "<fkField>": "new FK" }`. CAS `UPDATE ... WHERE public_key=? AND fk_column=expected`. Conflicting concurrent updates → **409**, missing identity → **404**, FK violation → **400**, unknown/malformed fields → **400**.
- Both runtimes log before and after to `protocolia_audit_event` in the same PostgreSQL transaction. Failure of audit persistence must roll back the FK change.
- Generated React uses an existing target-entity selector; it does not hardcode Ticket, Technician or field names. Reader role cannot submit, and a dedicated assignment capability is required at runtime.
- TypeSpec validation requires a required `@reference` field, a required 2-field request DTO, PATCH with 200/400/404/409, and explicit audit. Java and Nest revalidate the IR.
- Current limitation: one reassignment endpoint per entity in the generated UI; only the required non-nullable `restrict` reference profile; selection currently loads at most 50 related entities. IAM remains demo-only.

## A14.2 — Next query capability

Prefer explicit OpenAPI/TypeSpec typed query parameters and a **whitelisted filter IR** over inventing a user-controlled SQL expression language. Preserve `limit/offset` as a bounded stable sort, add typed equals/ranges, relationship filters, null/UTC semantics and generated indexes. Before implementation assess Spring JDBC/jOOQ OSS, NestJS Kysely/Knex and mature TypeSpec HTTP decorators; never concatenate untrusted identifier or data input.

## A14.3 — Domain events/notifications

A declarative, durable transactional outbox should link committed domain changes with deliveries. Evaluate PostgreSQL-native job libraries (Spring `db-scheduler`, Nest `pg-boss` or equivalent) and push/email channel adapters with retries, idempotency, due-time scans and receipts. Reject in-memory timers and new brokers as the sole durable delivery mechanism. No A14.3 runtime is implemented yet.
