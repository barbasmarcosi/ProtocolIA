## A14.2 — Reusable-query assessment (design, not implementation)

- **Contract:** reuse official TypeSpec HTTP `@query` and typed bounds, emitting OpenAPI 3.1 parameters; forbid arbitrary SQL expression strings. [TypeSpec decorators](https://typespec.io/docs/libraries/http/reference/decorators/).
- **IR:** one `filteredList` operation with an explicit allowlist of sortable/filterable fields, typed `eq`, `gte`, `lte`, FK-join chain, deterministic secondary identity sort, bounded limit/offset. Generate matching React filter controls and indexes only for declared high-selectivity joins/filters.
- **Spring:** retain existing `NamedParameterJdbcTemplate` and compose only compiler-verified column identifiers/where operators while binding all parameter values. Adding an ORM or jOOQ to the minimal JDBC profile before evidence of need would inflate builds/dependencies.
- **NestJS:** [Kysely](https://github.com/kysely-org/kysely) is an MIT-licensed mature typed SQL builder; evaluate a thin adapter using `pg` (already used) and compare generated query/plan, dependency footprint, and parameter safety against the existing `pg` runtime. Do not write a new generic query-language parser.
- **Acceptance:** cross-framework PostgreSQL query equivalence, permission before search, empty results, invalid ranges, combined FK/status/due date filters, deterministic pagination when rows tie, injection attempts, indexes via `EXPLAIN`, React mobile selector and zero destructive schema evolution.

## A14.3 — Durable event/delivery assessment (design, not implementation)

- **Contract:** express an event source, schedule/due rule, audience/channel and idempotency scope; exclude inline JavaScript or arbitrary SQL as a contract primitive.
- **Persistence:** transactional outbox in the same DB commit as business mutation; durable queue dispatcher, delivery attempts, delivery receipt, deduplication key, retry delay and dead-letter status. At-least-once execution plus idempotent side effects; never claim exactly-once external delivery.
- **Java:** evaluate [db-scheduler](https://github.com/kagkarlsson/db-scheduler), with persistent scheduled tasks and recovery, rather than a custom scheduler.
- **Node:** evaluate [pg-boss](https://github.com/timgit/pg-boss), supporting PostgreSQL-backed jobs, retries and singleton options; reuse the existing PostgreSQL deployment, no new broker.
- **Operations:** Render Free app sleep/restarts must not silently lose durable scheduled work; actual delivery latency/SLA remains unverified until a sustained worker is available. Email/push provider and user opt-in are separate external integrations.
- **Acceptance:** repeatable clock-injected overdue detection, restart/retry, dedup, provider outage, replay without double-send, tenant/permission isolation and inspectable receipts. Do not mark C16 PASS until these work end to end.
