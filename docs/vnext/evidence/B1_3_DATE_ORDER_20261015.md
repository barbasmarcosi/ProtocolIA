# B1.3 — Typed cross-field UTC date ordering (experimental)

## Contract semantics

A field annotated with @afterField("start") must be utcDateTime,
nonnullable, and strictly later than the required nonnullable utcDateTime
sibling "start". Optional target is allowed: the check applies when supplied.
No evaluator, arbitrary TypeSpec expression, executable rule body, or
application-specific generated templates.

## Compiler and runtime safeguards

- A TypeSpec decorator is lowered to canonical IR afterField as a safe field name.
- Compiler rejects missing, self, optional, nullable or non-temporal sources
  and mismatches with HTTP request DTOs.
- Nest and Spring validate the IR, emit PostgreSQL strict chronological CHECK,
  validate before writes and return field-specific 400 invalid_order.
- Date comparisons are by UTC instant, not text or naive clock order.
- This rule's wire precision is bounded to 0–3 fractional digits to match
  Node Date, Java truncated instants and browser comparisons.
- Generated React validates chronology with field errors and accessible focus.
- Missing optional target remains valid; malformed inputs fail closed.
- All prior enums, exact decimals, conditional-required fields and UX are retained.
