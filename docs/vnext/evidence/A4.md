## Límites y pendientes

- Se admite referencia **a la identidad pública string de otra entidad**, obligatoria y no nullable; política única de borrado `restrict`. Se rechazan entidades desconocidas, autorreferencia, referencias insuficientemente anchas, cascada y behaviors fuera del perfil.
- El selector React usa un listado de hasta 50 entidades relacionadas y evita aceptar un listado parcial silenciosamente. Búsqueda paginada/virtualizada queda pendiente si la tabla supera ese límite.
- Las operaciones declaradas para cada entidad son `create/get/listPage` y `delete` opcional. No se presupone incremento o renombrado cuando el contrato no los define.
- Siguen sin validar: E-07 real, relaciones múltiples/complejas, claves compuestas, migración de una base poblada a V2, autenticación productiva, y ejecución `app:test` sobre Docker Engine con `compose up`. El test Java se omitió con `-DskipTests`; la evidencia funcional proviene de HTTP/PostgreSQL/Chromium reales.
- **Decisión:** arquitectura modular GO para el perfil A4 probado. A4 PASS en el perfil acotado de dos entidades y referencias obligatorias restrictivas; variantes de relaciones y migraciones de bases existentes requieren capacidades posteriores. A2 conserva el bloqueo específico de Docker Engine; no se simula como PASS.

**Comando de construcción reproducible:**

```bash
npm ci
npm run app:build -- examples/vnext/equipment-inspections --target modular-spring --out dist/relations
```
