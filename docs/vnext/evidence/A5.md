## Límites obligatorios y bloqueo reproducible

- El algoritmo actual permite cambios en `view` y **adiciones opcionales, nullable, no únicas y sin referencias** sobre entidades existentes. Rechaza cambios de identidad, tipo, restricciones, eliminación de campos/entidades, operaciones, rutas y permisos. No genera automáticamente `DROP`, casts ni cambios destructivos.
- **No es un motor universal de migraciones**: entidades añadidas, relaciones nuevas, renombrado de campos, cambios de clave, dependencias de terceros y autenticación de producción necesitan extensiones deliberadas.
- Conserva extensiones en `extensions/` y `.env` de la app; no admite editar código gestionado ni distribuir customizaciones dentro de los directorios generados.
- La sustitución del output conserva la versión anterior como copia de respaldo; el backup del **directorio** no equivale a un backup consistente de PostgreSQL. Una vez aplicada V2, el downgrade automático de base no está implementado. No utilizar con producción sin backup y recuperación.
- Un primer ensayo dentro de una capa de Docker no pudo renombrar un directorio proveniente de una capa anterior (`EXDEV`). Se detuvo sin mutar la app ni DB. Se repitió sobre una **copia aislada en la capa actual**, y la sustitución terminó correctamente. El mecanismo falla cerrado si el sistema de archivos no admite rename; no intenta un borrado destructivo para esquivar `EXDEV`.
- `app:test` sobre un Docker Engine real sigue **NOT RUN** por ausencia de daemon accesible. La conformance PostgreSQL/HTTP/Chromium se ejecutó en el Docker build aislado.

## Comandos para un checkout limpio

```bash
npm ci
npm run app:build -- examples/vnext/equipment-inspections --target modular-spring --out dist/relations
# Después de modificar únicamente los contratos TypeSpec compatibles:
npm run app:plan -- examples/vnext/equipment-inspections dist/relations
npm run app:evolve -- examples/vnext/equipment-inspections dist/relations
```

Una app antigua **sin `protocolia-ownership.json`** no se puede evolucionar de forma segura en su lugar; primero se reconstruye desde su contrato original en un árbol limpio y se comprueba que coincide con el esquema preexistente. La entrega no requiere GitHub Actions ni APIs pagas.
