## Componentes modificados

- `packages/adapters/modular/generate.mjs`: emite `db/migration/V1__contract_baseline.sql` con firma de esquema en vez de `schema.sql` silencioso; valida rutas, status, capacidades y primitivas antes de producir archivos.
- `packages/adapters/modular/templates/pom.xml` y `application.properties`: dependencias oficiales `spring-boot-starter-flyway` + `flyway-database-postgresql`, validación de migraciones y `clean` deshabilitado.
- `packages/compiler/src/index.ts` y tipos del IR: comportamiento `delete` explícito, éxito 204 obligatorio.
- `DomainRuntime.java`: `DELETE` genérico, transaccional, basado en identidad pública, y errores 404/204 correctos.
- Contrato `Gauge` y pruebas HTTP: `delete` definido por contrato; no se agregó a `Tool` ni se copió ninguna implementación por entidad.

## Límites explícitos

A1 sólo acredita el perfil mononentidad/TypeSpec actual y la autenticación **Basic demo opt-in** con credenciales efímeras. No existen aún OIDC/JWT productivo, operaciones arbitrarias, relaciones FK, migraciones incrementales aprobadas, ni un ciclo de regeneración sobre DB preexistente con cambios compatibles. El sello de Flyway impide alterar V1; **no** genera V2 automáticamente. El API HTTP sigue atendido por el runtime genérico; las interfaces OpenAPI Generator están compiladas pero no cableadas como delegates tipados. Maven usó `-DskipTests`; la evidencia funcional proviene de pruebas HTTP/PostgreSQL/Chromium reales. El compilador npm reporta 1 aviso moderate y 1 high que requieren triage previo a distribución. No se modificó P3/P4/G0–G5, `main` ni el demo manual.

**Siguiente etapa:** A2 — CLI única de compilación, frontend sensible a roles/errores y empaquetado reproducible; después A3/A4/A5.
